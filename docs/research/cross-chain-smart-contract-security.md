# Cross-chain security rules for the Jose Sui Move skills

## Scope and conclusion

This audit compares the seven current `SKILL.md` files with primary, first-party security guidance from Solidity, OpenZeppelin, Ethereum standards, Mysten/Sui framework source, the Move language reference, and (for oracle integration only) Pyth's own integration guidance.

The baseline standard was already stronger than a generic checks-effects-interactions checklist. It explicitly ordered guards, computed and validated proposed final values before mutation, used typed authority, bounded state and work, reconciled assets, isolated adapters, locked callback-capable handoffs, scoped pauses, operationally gated Sui upgrades, and required adversarial/property tests. The smallest useful changes were therefore narrow: account for dependency linkage during cutovers; add oracle freshness and adversarial-selection rules; make signed actions safe under third-party submission; document asset admission assumptions; prove authority-destruction liveness; and add Sui randomness/composition safety. The working tree implements all six. Most EVM proxy and ERC-20 prescriptions should not be imported.

| Fail-fast guards and validate-before-mutate | Solidity says all parameter checks precede state effects; Move aborts revert the whole transaction and cannot be caught ([Solidity security considerations](https://docs.soliditylang.org/en/latest/security-considerations.html), [Move `abort`](https://move-language.github.io/move/abort-and-assert.html)). | Upgrade, linkage, and storage compatibility | OpenZeppelin proxy upgrades must preserve EVM storage-slot order/types and must initialize and lock implementation contracts ([writing upgradeable contracts](https://docs.openzeppelin.com/upgrades-plugins/writing-upgradeable)). ## Why several EVM rules do not transfer literally

1. **Do not turn CEI into “every external call last.”** Sui Move calls are statically named module functions, assets are values rather than addresses with automatic fallback code, and an abort atomically discards effects. Required external reads must occur before proposed-value computation. Preserve the existing rule: validate cheap local facts first, isolate hostile adapters, and lock only an explicitly callback-capable handoff. Move's reference/ability system prevents many aliasing and asset-copy bugs at compile time ([Move references](https://move-language.github.io/move/references.html), [Move abilities](https://move-language.github.io/move/abilities.html)).

2. **Do not import EVM proxy storage recipes.** Sui upgrades publish new immutable package versions and preserve old code; the main hazards are old entry points, immutable public type layouts/signatures, dependency identity, and object migration. The current operational version gate directly addresses the old-code hazard. EVM storage gaps, ERC-7201 namespaces, constructor-to-initializer conversion, `delegatecall`, and implementation takeover are not Sui Move mechanisms.

3. **Do not import ERC-20 transfer/allowance folklore wholesale.** Native `Coin<T>` transfer does not call token-defined fallback code and has no ERC-20 Boolean-return ambiguity or allowance race. The transferable lesson is to validate the asset's actual policy: type origin, mint authority, regulation/global pause, units, and balance deltas.

4. **Do not port `tx.origin` advice as a Sui rule.** Sui does not expose the EVM `msg.sender`/`tx.origin` split. The relevant Sui rule is already better: ownership enables an object to be supplied, but privileged protocol authority should be an explicit typed capability or a live-validated witness; anyone can submit a transaction that uses a shared object, and Sui warns that `tx_context::sender()` alone can break intended composition ([Sui security best practices](https://docs.sui.io/develop/security/best-practices#access-control), [shared objects](https://docs.sui.io/develop/objects/object-ownership/shared#security-considerations)).

5. **Rollback is not always a defense.** It supports validate-before-mutate, but with randomness it enables selective abort and retry. Rules must reason about who can compose later commands and choose whether the transaction commits.

## Baseline coverage by skill file

- `ask-jose`: routing is accurate; it already sends authority, asset, lifecycle, and shared-state work through security and testing. Only its security summary may need “oracle and randomness” if those rules are added.
- `jose-move-architecture`: already covers minimal state, typed capabilities, bounded collections, adapter isolation, immutable pins, and economic assumptions. No broad change needed.
- `jose-move-events-errors`: already makes guard precedence, replay facts, and conservation diagnostics stable. The researched gaps are not event-schema rules.
- `jose-move-review`: correctly loads all substantive standards and traces guards through mutation/assets/emission. It will inherit most additions; optionally name oracle freshness and signature front-running in its risk trace.
- `jose-move-security`: owns all six substantive additions below.
- `jose-move-source-style`: already preserves evaluation/abort order, checks pinned framework source, minimizes abilities, and documents invariants/bounds. No change needed.
- `jose-move-testing`: already covers almost every researched risk. Add only oracle-selection/staleness, third-party signature submission, authority-destruction liveness, and randomness selective-abort cases when applicable.

## Prioritized smallest reusable skill changes

1. **Dependency-linkage rule (`jose-move-security` and `jose-move-testing`):** a dependent does not follow a dependency upgrade automatically; retain and test an explicit re-link or retirement path before activating a cutover or making the dependent immutable.
2. **Oracle/time rule (`jose-move-security`, matching adversarial test):** use canonical `Clock`; validate oracle/feed identity, units, freshness, update time, confidence/deviation, and caller-selectable update behavior before economic computation. Pin deadline boundary semantics and user-approved min/max outcomes.
3. **Signature-submission rule (`jose-move-security` and `jose-move-testing`):** distinguish authenticated actor from transaction submitter; front-running or third-party submission must fail harmlessly or produce exactly the signer-approved effect.
4. **Asset-admission rule (`jose-move-security`):** document and verify type origin, mint/supply authority, restrictions/global pause, units, and authoritative balance delta; reject assets that can break mandatory settlement or exits unless an accepted threat model explicitly bounds the risk.
5. **Irreversible-authority liveness rule (`jose-move-security` and one test bullet):** before burn, renounce, or final handoff of root/upgrade authority, prove successor usability and required recovery/exit liveness.
6. **Randomness rule (`jose-move-security` and `jose-move-testing`, conditional only):** defend against public composition plus conditional abort/retry; do not suppress `public_random` without a proof and adversarial test.

## Recommendations rejected

- **Redundant:** generic CEI, generic “validate inputs,” blanket reentrancy guards, least-privilege prose, universal pause/failsafe, loop bounds, conservation equations, property tests, exact failures, replay nonces, upgrade digest checks, and storage/ABI compatibility. The skills already state stronger Sui-specific versions.
- **EVM-specific:** `tx.origin`, forced Ether, `transfer`/`send` gas stipends, ERC-20 Boolean/no-return and allowance-zeroing patterns, fallback hooks on native coin transfer, proxy storage gaps/namespaces, constructors-as-initializers, `delegatecall`, `selfdestruct`, and implementation-contract takeover.
- **Context-costly:** mandatory multisig/timelock for every admin, mandatory separate pauser/unpauser, mandatory TVL caps, universal formal verification, universal commit-reveal, and speculative governance or recovery hooks. These can be correct for a concrete threat model, but making them global skill rules would conflict with the existing requirement to avoid speculative roles and mechanisms.
